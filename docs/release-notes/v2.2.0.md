# signal-mod v2.2.0 - Review fixes

**Date:** 2026-11-11 · **Compare:** `v2.1.1...v2.2.0`

Fixes from an independent review. No breaking API change; MSRV
unchanged (1.85); no new dependency.

## Added

- `SignalSet::stop()`: SIGTERM and SIGINT, without SIGHUP.
- `From<signal_mod::Error> for std::io::Error`: `install()?` and
  `shutdown_signal()?` work in `io::Result` functions.

## Fixed

- A `notify_signals(Hangup)` reload subscription on the default builder
  no longer stops the process: a notify signal leaves the default
  shutdown set.
- Unix: under `nohup`, the default set no longer catches the ignored
  SIGHUP, so the process keeps running when its terminal hangs up.
- Windows: a user logoff no longer stops (or reloads) a service, and no
  longer leaves a parked thread behind. `CTRL_LOGOFF_EVENT` is declined;
  `CTRL_SHUTDOWN_EVENT` is now `Terminate`.
- `force_exit_on_second_signal` escalates only on a repeat of the first
  signal (or Ctrl+C and `Quit` together), so SIGTERM followed by SIGHUP
  no longer kills the process before its hooks run.
- Unix: a shutdown signal arriving during `install()` is no longer lost.

## Behaviour changes to check

- An explicit `signals(..)` set is used exactly as before. Only the
  implicit default changes: notify signals leave it, and on Unix signals
  ignored at start-up stay ignored.
- On Windows, code that listened for logoff through `Hangup` no longer
  receives it; machine shutdown arrives as `Terminate`.

Every fix has a regression test.
