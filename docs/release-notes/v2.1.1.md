# signal-mod v2.1.1 - Pre-1.0 review

**Date:** 2026-11-04 · **Compare:** `v2.1.0...v2.1.1`

A review of the whole crate for security, edge cases, and idle cost.
No public API change; MSRV unchanged (1.85); no new dependency.

## Fixed

- A hook panic whose payload panics again when dropped no longer kills
  the hook worker: the hook is reported `Panicked` instead of hanging
  the run until its deadline (or forever).
- A task waker that panics during shutdown no longer stops the other
  tasks from being woken, or kills the signal listener (on Unix every
  later signal was lost).
- Windows service: status reports reach the service control manager in
  the order they are made, and nothing is sent after `STOPPED`.
- Windows service: a stop control after shutdown has begun no longer
  ends the process without the `STOPPED` report.
- Windows, with `force_exit_on_second_signal`: console close, logoff,
  and system shutdown no longer count as a second signal; only Ctrl+C
  and Ctrl+Break escalate. A service gets both a shutdown control and a
  console shutdown event for one machine shutdown, and the second used
  to end the process before its hooks ran.
- `Coordinator::uninstall` holds its lock until the listeners are gone,
  so a racing `install` cannot run beside them.

## Changed

- `run_hooks_async` with no hooks resolves on its first poll: about
  64 us to 160 ns on Windows.

## Documentation

- `docs/API.md` gains a "Known limitations" section, each limitation
  with its reason.

Every fix has a regression test; `tests/idle.rs` checks that an
installed coordinator causes no idle wake-ups on Linux.
